# IPSec VPN Port-Forwarding - 20260618

Before we get started on doing anything IPSec VPN related, we need to have port-forwarding enabled on our router. This is a prerequisite to continuing with this section.<br>
For site-to-site IPSec, one of our ends has to have their ports open to ACK-SYN and open a connection. Since the goal is to connect from my work/office enviornment, I need the ports on my home router to be open.

Everyone's router settings will be different, but we'll just walk through how my process was.<br>
But first for all the noobs out there, why are we port forwarding to begin with?<br>
When traffic from our IPSec arrives at our public ip, our router will recieve it but have no idea what to do with it. Then it gets dropped. So by setting up port forwarding, we're telling our router that if it sees traffic on UDP 500 for example, send it to our Fortigate.

So let's get Fortigate set up for that. Log into the console `sudo virsh console fortigate` and run `show system interface port1` for the ip address (which you should know already anyway) and `diagnose hardware deviceinfo nic port1` for the MAC address.<br>
The MAC address will be listed as "Permanent Hwaddr".<br>
Note both the ip and MAC address somewhere because we'll need them later.

Next log into your home router's webpage. The address is usually `<your gateway ip>/login`. Usually the login and password is "admin" and "password", but if you're unsure, there should be a sticker on your router somewhere with the login info.

Now we're gonna reserve a static ip for our Fortigate.<br>
You'll wanna find somewhere in your setup an area that says something along the lines of "DHCP Reservations". I provided an image of what that looks like on my router. But you'll notice it has boxes to fill in your MAC address and ip. Go ahead and fill that in. Then save it. Your router is then going to reset itself. Great, now that ip is permanently reserved for our Fortigate's port1.<br>
![alt text](images/fortigate-ipsec/dhcp-reservation.png)

Next up is to create port forwarding rules.<br>
For this lab, we're going to open up ports UDP 500 and UDP 4500. Let's get into the reasons for that.<br>
→ UDP 500: This is used by IPSec for the initial handshake, the IKE (Internet Key Exchange). Later on in part 2 of this tutorial we'll talk more about this, but for now it's just where both Fortigates agree on encryption and authentication.<br>
→ UDP 4500: This is used for NAT traversal. Our Fortigate is behind our router, which is basically NAT. And in order for our IPSec traffic to survive passing through NAT, it needs to be wrapped in UDP 4500.<br>
In normal enterprise situations, Fortigate is usually always placed before the router, however, I have no intention to use my Fortigate for anything other than my home server (I don't want it touching my other devices), so I don't need it outside my router.

So let's log back into our router's webpage.<br>
We're looking for something related to port forwarding. Below is what it looks like on my end.<br>
![alt text](images/fortigate-ipsec/port-forwarding.png)
→ Port Start~End: These are the port numbers to forward. We're only focused on single ports, so the start and end will be the same.<br>
→ Protocol: UDP or TCP. IPSec uses UDP.<br>
→ Local: This is the ip on our internal network to forward to Fortigates port1 ip<br>
→ External:  This will stay as is. Basically it means "from any external ip".

Let's make our first rule. IPsec IKE.<br>
```
Description: IPSec-IKE
Protocol: UDP
Port Start: 500 (local and external)
Port End: 500 (local and external)
Local: <your Fortigate's port1 ip>
External: 0.0.0.0
```
Then click Activate then Apply.

Rule 2, IPSec NAT-T.<br>
```
Description: IPSec-NAT-T
Protocol: UDP
Port Start: 4500 (local and external)
Port End: 4500 (local and external)
Local: <your Fortigate's port1 ip>
External: 0.0.0.0
```

Cool. Now you're all set to move onto the next tutorial, `2.1_IPSecVPN-Site-to-Site.md` and `2.2_IPSecVPN-Dialup.md`!

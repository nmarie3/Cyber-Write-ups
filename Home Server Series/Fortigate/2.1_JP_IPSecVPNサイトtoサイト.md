# Site-to-Site IPSec VPN - 20260618
### AI翻訳です。

このプロジェクトの目的は、自宅サーバーを職場に置いてあるFortigateのテスト機器に接続することだ。せっかくテスト用の機材があるんだから活用しようと思ってな。ちゃんと動いてるか確認するために、このドキュメント自体をVPN越しに送ってみることにした。動作確認も兼ねてってわけ。（結果から言うと、できた！）

そもそもIPSecって何で、なんで使うの？<br>
TCP/IPプロトコル自体にはセキュリティ機能がない。IPSecはそこにセキュリティを追加するためのものだ。後ほど触れるセキュリティ機能のおかげで、かなり堅牢な通信手段になる。VPNの中でも上位に入る方式だよ。

IPSecには「エンドツーエンド」と「サイト間」の2つのモードがある。<br>
技術的な違いを言うと、サイト間（トンネルモード）は元のIPヘッダーとペイロードを丸ごとカプセル化した上で、新しいIPヘッダー（パブリックIP）を付加する。一方のエンドツーエンド（トランスポートモード）はペイロードだけを保護し、元のIPアドレスはヘッダーに丸見えのまま残る。<br>
シンプルに言うと、サイト間は2つの固定ネットワーク同士をつなぐもの。例えば支社と本社みたいな感じ。<br>
エンドツーエンドは「リモートアクセス」として知られているもので、ユーザー端末をネットワークに接続する方式だ。Fortigateでは「ダイヤルアップVPN」と呼ばれる。<br>
このチュートリアルはサイト間の接続のみを扱う。リモートアクセスについては `2.2_IPSecVPN-DialupVPN.md` を参照。

始める前に、少なくとも一方のルーターでIPSecのポートフォワーディングを設定しておく必要がある。やり方は `2.0_IPSecVPN-Port-Forwarding.md` を参照。

それから、両方のデバイスのWAN IPも必要だ。FortigateのIPはダッシュボードの「Status」にあるSystem Informationウィジェットから確認できる。<br>
WAN IPが「Unknown」と表示されている場合は、`whatismyip.com` で確認できる。<br>

よし、さっそくFortigateでIPSecを設定していこう。<br>
Fortigateのバージョンによってはこれと画面構成が異なることもあるけど、手順は同じだ。

FortigateのGUIにログインしたら、VPN > VPN Tunnels に行って「Create new > Custom IPsec tunnel」をクリック。

![alt text](images/fortigate-ipsec/ipsec-tunnel.png)

[UIが異なる場合]

![alt text](images/fortigate-ipsec/custom.png)

名前を入力してIPアドレスを記入。Interfaceは「port1」を選択。

![alt text](images/fortigate-ipsec/warning.png)

ただ……ここでエラーが出る。port1を割り当てると、GUIの管理アクセスが失われるんだ。IKE TCPとHTTPSは同じポートで動かせない。なので選択肢は2つ。<br>
アクセス喪失を受け入れて、port2からGUIにログインする。<br>
管理用ポートを443から別のポートに変更する。

自分は2を選んだ。なんでかって？　1の苦労をすでに経験済みで、接続が不安定だったから。<br>
もう少し詳しく説明すると、パケットインスペクションポリシーはIKE TCP（ポート443）とHTTPS管理トラフィックを区別できない。つまり、管理GUIに向かうべきトラフィックが誤ってIKEトラフィックと見なされてしまう可能性がある、という警告だ。

System > Settings に移動して、HTTPSポートを443以外に変更しよう。よく使われるのは8443。変更を適用するとサインアウトされるので、次からは `https://<fortigate-ip>:<新しいhttpsポート番号>` でログインすること。例：192.168.0.32:8443。

![alt text](images/fortigate-ipsec/https-port.png)

VPNトンネルの設定に戻ろう。<br>
さっきの管理アクセスの警告は消えているはずだ。
じゃあ、接続先の名前を入力しよう。<br>
テンプレートタイプがデフォルトで「Site to Site」になっているけど、ここは「Custom」を選択する。そしてNextへ。<br>
画面はこんな感じになるはず。

![alt text](images/fortigate-ipsec/newvpn.png)

名前は接続先の名前などにしておくとわかりやすい。Remote Gatewayは固定IPなら「Static IP Address」のまま。DDNSを使っているなら「Dynamic DNS」を選んで、接続先のIP/DDNSを入力する。<br>
自分の場合、職場FortigateのパブリックIPが頻繁に変わるので、DDNSを使っている。
補足：リモートゲートウェイにDDNSで接続したい場合はDDNSを設定することもできる。ルーターのパブリックIPが変わりやすい環境（例：CGNAT）では特に重要だ。DDNSの設定方法については `3_Dynamic-DNS-Setup.md` を参照。<br>
なお、無料のFortigate VMではDDNSは作成できない。実機かサブスクリプションが必要だ。

Interfaceはwan/wan1に変更する。ほとんどの場合はwanでOK。インターネット側に向いているポートがそれだから。別のポートを使っている場合はそちらを選択。

Networkの残りのフィールドはデフォルトのままでいい。

注：Fortigateを頻繁にシャットダウンする予定があって（しかも事前にトンネルを落とすのを忘れがちな）場合は、Dead Peer Detectionを「On Idle」に設定するのをおすすめする。Dead Peer Detectionは各ピアが相手の生存を確認する機能で、応答がなければ接続を切断する。「On Demand」はアクティブなトラフィックがある時だけ検出する。だが起動元の機器をシャットダウンした場合、相手側のピアがそれをデッドトンネルとして認識できないことがある。接続が固まって再接続されなくなるわけだ。「On Idle」にしておけば、トラフィックの有無に関わらず能動的に確認してくれる。

## HAGLE - 認証、フェーズ1・フェーズ2
### 認証 (Authentication)

この先のカテゴリーでは5つの重要なセキュリティネゴシエーションが行われる。それをまとめたのが「HAGLE」という頭文字だ。残念ながらFortigateの設定画面はこの順番通りに進まないけど、出てきた順に解説していく。<br>
H - ハッシュアルゴリズム（Hashing Algorithm）<br>
A - 認証（Authentication）<br>
G - Diffie-Hellmanグループ（秘密鍵交換）<br>
L - ライフタイム（トンネル持続時間）<br>
E - 暗号化（Encryption）

まず「A」、接続相手の身元確認から。<br>
「Pre-shared Key（事前共有鍵）」では、両デバイス間で共有する鍵を設定する。最初に接続を試みた時点でお互いを認証するためのもので、鍵が一致しなければ接続できない。<br>
どんなパスワードでも使えるが、長めにして数字や記号も入れること。<br>
「Signature（署名）」に切り替えることもできるが、その場合はRSAデジタル署名が必要になる。

署名方式との違いは、事前共有鍵と違って相手を事前に知らなくても接続できる点にある。仕組みとしては：<br>
ユーザーAのデータハッシュを暗号化する。<br>
暗号化されたハッシュをデータとともにユーザーBに送る。<br>
ユーザーAの公開鍵で復号する。<br>
復号した値とデータのハッシュを照合する。<br>
一致すれば、元のデータであること・転送中に改ざんがないことが確認できる。<br>
まあとにかく、RSAデジタル署名を自分で生成してCA（認証局）からデジタルID発行を受けて…という手順が必要になるので、今回はやらない。

次はIKE（Internet Key Exchange）の選択。<br>
これは2つのデバイスが暗号鍵を交換し、暗号化パラメーター（セキュリティアソシエーション、SA）についてネゴシエーションする仕組みだ。<br>
IKE1は技術的にはもうサポート外（設定はまだできるけど）で、IKE2がモダンかつより安全な選択だ。

![alt text](images/fortigate-ipsec/auth.png)

### フェーズ1プロポーザル (Phase 1 Proposal)

フェーズ1は、トラフィックを暗号化するための鍵を安全にネゴシエーションするためのトンネルを確立するフェーズだ。鍵はこのフェーズで作ったトンネルを通じて交換される。

ここで選んだ内容は接続先デバイスでも必ず一致させること。これが暗号化パラメーターのネゴシエーションになる。ついでに各項目について少し説明しよう。

HAGLEの「E」、暗号化アルゴリズムだ。ドロップダウンを開くと色々な選択肢が並んでいる。AES128がよく使われるのでデフォルトになっている。気になる人は各アルゴリズムについて調べてみて。ただし無料VMのFortigateは使える暗号化に制限があって、DESしか使えない。これはデータ整合性を検証するためのアルゴリズムだ。

![alt text](images/fortigate-ipsec/hashing.png)

Authentication（認証）のドロップダウンも同様。どのハッシュを認証に使うかを選ぶ、HAGLEの「H」にあたる部分だ。複数の種類を選んでもOK。増やすほど複雑になる。

次は「G」、Diffie-Hellmanグループ。2つのVPN機器が、鍵自体を送信せずにInsecureなネットワーク上で安全に共有秘密鍵を確立するためのプロトコルだ。

![alt text](images/fortigate-ipsec/dh.png)

仕組みがなかなか面白い。画像を見てみて。<br>
数学的な部分をわかりやすく視覚化したものを探してみた。これが自分的には一番理解しやすかった。

![alt text](images/fortigate-ipsec/dh-math.png)

グループ番号も複数選べるけど、このラボでは14だけ使う。グループ番号が大きいほど暗号強度は上がるが、計算に必要な処理能力も増えるので注意。<br>
グループ1と2は廃止済みで使うべきじゃない。<br>
グループ5も非推奨。<br>
グループ14が標準的なベースライン。<br>
グループ19と20は次世代暗号化として強く推奨。<br>
グループ21は標準的な暗号強度の中では最高レベル。

最後は「L」、トンネルのライフタイム。<br>
鍵を更新する頻度のこと。デフォルトは86,400秒、つまり24時間（1日1回）。このままにしておく。

![alt text](images/fortigate-ipsec/lifetime.png)

### フェーズ2セレクター (Phase 2 Selectors)

フェーズ2は、データトラフィックの暗号化に使う方式についてVPN機器同士がネゴシエーションするフェーズだ。この交換が完了すると、以降のすべてのデータトラフィックはこの2つ目のトンネルで暗号化される。

![alt text](images/fortigate-ipsec/createp2.png)

「Create new」ボタンをクリック。<br>
「Name」が自動入力されない場合は、上で付けた名前と同じにするか好きな名前にしてOK。わかりやすくするためここでは同じ名前にしておく。

「Local Address」は自分側の送信元ネットワーク。<br>
ローカルアドレスとサブネットがわからない場合は、左サイドバーのNetwork > Interfaces から port2（LAN側ポート）を確認。

![alt text](images/fortigate-ipsec/phase2.png)
![alt text](images/fortigate-ipsec/lan.png)

特定のIPだけでなくサブネット全体を許可する場合は、IPの末尾オクテットを0にしてサブネット全体をカバーさせること。<br>
特定ユーザーだけを絞りたい場合はFirewall Policyで制限した方がいい。

「Remote Address」は接続先のローカルIPを同様に入力。

終わったら「Advanced」の「+」をクリック。フェーズ1と同じ内容だが、ここでもデバイス間で設定を一致させること。

「Auto-negotiate」と「Auto Keep Alive」は必ず有効にしておく。<br>
これを有効にしておくと、VPNが切断された際にフェーズ2のネゴシエーションを5秒ごとに再試行し続けてくれる。つまり自動的に再接続しようとしてくれるわけだ。

![alt text](images/fortigate-ipsec/autonegotiate.png)

OKをクリックし、さらにOKをクリック。

## スタティックルート (Static Routes)

次はトラフィック用のスタティックルートを作成する。職場のサブネット宛てのトラフィックはIPSecトンネルを通すべきで、通常のWANに流してはいけない。これを設定しないと、自宅からのトラフィックはインターネット上で迷子になる。

Network > Static Routes に移動して「Create New」をクリック。

![alt text](images/fortigate-ipsec/staticroute.png)

「Destination」は接続先のLANサブネット。<br>
「Interface」は今作ったIPSecトンネルを選択。<br>
「Distance」はそのままでOK。そしてOKをクリック。

## ポリシーとオブジェクト (Policy & Objects)
### アドレス (Addresses)

ファイアウォールポリシーを作る前に、アドレスオブジェクトを作成しておく必要がある。これはポリシーの中でIPを直接書く代わりに参照として使えるもの。一度作っておけば複数のポリシーで再利用できるし、IPが変わった時はオブジェクトを更新するだけで全ポリシーに反映される。IPアドレスをそのまま書き並べるより読みやすくもなる。

Policy & Objects > Addresses > Create new へ。<br>
名前を付けてIPサブネットを入力。<br>
自宅と接続先、両方のLAN IPでこれをやっておく。

![alt text](images/fortigate-ipsec/addresses.png)
![alt text](images/fortigate-ipsec/addresses2.png)

### ファイアウォールポリシー (Firewall Policy)

IPSecトンネルには2つのファイアウォールポリシーが必要だ。送信用と受信用。なお無料VMのFortigateはポリシーが3つまでの制限があるので、これを作ると残り1つになる。

Policy & Objects > Firewall Policy > Create New へ。<br>
自宅から接続先へのトラフィックだとわかる名前を付ける。<br>
「Action」はACCEPTに設定。<br>
「Incoming interface」はport2（またはLAN側ポート）。<br>
「Outgoing interface」はIPSecトンネル。<br>
「Source」は先ほど作成した自宅LAN用のアドレスオブジェクト。<br>
「Destination」は接続先LAN用のアドレスオブジェクト。<br>
「Service」は特定のサービスだけを通したい場合以外はALLでOK。<br>
NATが有効になっている場合は無効にすること。<br>
スクロールして「Logging Options」を見つける。デフォルトはセキュリティアラートのみだが、トラブルシューティングのために「All sessions」に変えておくといい。

![alt text](images/fortigate-ipsec/policy1.png)
![alt text](images/fortigate-ipsec/allsessions.png)

OKをクリックして、次は2つ目のポリシーを作成。同じ手順で、今度はすべて逆方向にする。<br>
→ 名前は接続先から自宅へのトラフィックを示すもの。<br>
→ ActionはACCEPT。<br>
→ Incoming interfaceはIPSecトンネル。<br>
→ Outgoing interfaceはport2（LAN側）。<br>
→ SourceはリモートLANサブネットのアドレスオブジェクト。<br>
→ Destinationは自宅LANサブネットのアドレスオブジェクト。<br>
→ ServiceはALL。<br>
→ NATは無効。

ここまで終わったら、接続先のFortigateでも全く同じ手順で、方向を逆にして設定すること。

### トンネルを起動する

設定が完了したら、ポートフォワーディングを設定していない方のFortigateから操作する。自分の場合は自宅ルーターでポートを開放したので、トンネルの接続を受ける側は自宅だ。つまりポートフォワーディングを設定していない方（職場側）からトンネルを開始する（両側に設定した場合はどちらからでもOK）。

VPN > IPsec/VPN Tunnels に戻り、Statusが「Inactive」になっているトンネルをクリック。Statusの列の文字の上をクリックしないと反応しないので注意。

![alt text](images/fortigate-ipsec/status-click.png)

トンネルをクリックすると上部に「Bring Up」と「Bring Down」の2つのボタンが表示される。「Bring Up」をクリックして、起動するフェーズ2セレクターを選択。

![alt text](images/fortigate-ipsec/phase2-bringup.png)

少し時間がかかることもあるし点滅することもあるが、接続が確立されると赤い下向きの丸が全部緑の上向きに変わる。Peer IDも表示される（自宅サーバーのport1 IP）。

![alt text](images/fortigate-ipsec/bringup-success.png)

### スタティックルートの追加

次の問題は、各ルーターがそれぞれのFortigate/トンネルの存在を認識しているかどうかだ。各PCやサーバーにスタティックルートを追加するか、各ルーターに追加するかで解決できる。自分はテストに1台のPCしか使っていなかったので、PCとサーバーにルートを追加した。<br>
以下のコマンド（Windows向け）は、デフォルトゲートウェイ（職場ルーター）に対して「自宅サーバー宛てのトラフィックはルーターではなくFortigateに送れ」と指示するものだ。<br>
`route add -p <自宅FortigateのLANサブネットIP> mask 255.255.255.0 <職場FortigateのLAN IP>`<br>
次のコマンドはLinuxサーバー用。職場からのトラフィックを受信した際に、デフォルトゲートウェイ（自宅ルーター）ではなくFortigateを経由するよう指示する。<br>
→ -p で永続化する。<br>
`sudo ip route add 192.168.0.0/16 via <自宅FortigateのLAN IP>`<br>
→ /16のマスクにしている理由は、職場PCのサブネットと職場FortigateのサブネットIPが異なるため、サブネットを問わずカバーする必要があったから。

ルーターにスタティックルートを設定したい場合は……

職場ルーターのスタティックルート：<br>
宛先IP：`<自宅FortigateのサブネットIP>`<br>
ゲートウェイ：`<職場FortigateのLAN IP>`

自宅ルーターのスタティックルート：<br>
宛先IP：`<職場FortigateのサブネットIP>`（全サブネットをカバーするため192.168.0.0/16）<br>
ゲートウェイ：`<自宅FortigateのWAN IP>`

以上だ！<br>
接続確認は、相手側FortigateのLAN IPにpingを打ってみればいい。ブラウザからそのFortigateのGUIにアクセスすることもできる（変更したポート番号を忘れずに！）。

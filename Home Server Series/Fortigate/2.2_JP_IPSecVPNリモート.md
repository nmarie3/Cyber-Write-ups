# ダイヤルアップ IPSec VPN - 20260627
### AI翻訳です。

前回のチュートリアルではサイト間IPSec VPNを構築した。今回はリモートアクセスVPN、つまりFortigateコンソールでいう「ダイヤルアップ」をやっていく。サイト間との違いは、どこからでもリモートデバイス1台でFortigateネットワークに接続できる点だ。在宅勤務の社員がオフィスネットワークに繋いでファイルにアクセスする、みたいな用途によく使われる。<br>
リモート接続にはFortiClient VPNを使う。無料で使える「VPN専用」バージョンがあるのでそれをダウンロードしておこう。`https://www.fortinet.com/support/product-downloads` ページの一番下にある。まずそれを落としておくこと。

![alt text](images/fortigate-ipsec/vpn-only.png)

## ユーザーグループの作成

まずユーザーグループを作り、続いてユーザーアカウントを作る。このユーザーは後でVPNをテストするときにサインインに使う。User & Authentication > User Groups > Create new へ行き、グループ名をつけてTypeを「Firewall」に設定する。グループを作っておくと、複数ユーザーを同じポリシーにまとめて割り当てるのが楽になる。ユーザーを先に作ってもグループを先に作ってもどちらでもいい。ユーザーを先に作った場合はMembersの「+」をクリックして追加すればいい。まだユーザーがいないなら空白のままで構わない。後でユーザー側からグループに追加できる。

![alt text](images/fortigate-ipsec/usergroup.png)

## ユーザーの作成
次はログイン用のユーザーを作る。同じカテゴリからUser Definition > Create new へ。ここはLocal Userのままにして、Nextをクリック。

![alt text](images/fortigate-ipsec/newuser.png)

Login CredentialsでユーザーIDとパスワードを設定してNext。<br>
Contact Infoは無料版だと二要素認証が選べないのでそのままNextで飛ばす。<br>
Extra Infoは User Account StatusをEnabledのままにして、User Groupのスライダーをオンにする。ここで先ほど作ったグループを追加できる。できたらSubmit。

![alt text](images/fortigate-ipsec/extra-info.png)

## ファイアウォールアドレスの作成

ここまで終わったら、接続先のローカルサブネット用にファイアウォールアドレスを作る必要がある。<br>
これはサイト間VPNの設定でHomeLab用とOffice用のアドレスを作ったときとまったく同じ作業だ。改めて理由を説明すると、ポリシーにIPアドレスを直打ちする代わりに名前で参照できるようにするためで、一度作っておけば複数のポリシーで使い回せる。IPが変わっても、オブジェクトを更新するだけで関連するすべてのポリシーに反映される。IPを見るよりポリシーが読みやすくなるというメリットもある。<br>
テスト用に 10.1.1.0/24 のローカルサブネットを使う。

![alt text](images/fortigate-ipsec/firewall-address.png)

## ダイヤルアップVPNトンネルの作成

いよいよVPNトンネルを作っていく。<br>
VPN Tunnels > Create new > Custom IPsec tunnel（UIの見た目によって多少違う場合がある）へ。<br>
バージョンによってUIが異なることがあるが、設定項目は基本的に同じだ。<br>
→ VPN名をつける。ここでは「remote-test」にした。Remote gatewayはDialup userを選択。古いバージョンだと「Remote Access」と表示される場合があるのでそちらを選ぶこと。これはどのタイプのVPNトンネルを作るかを指定している。<br>
→ Interfaceは外部からのトラフィックが入ってくるポート、つまりWAN側のポートを選ぶ。今回はport1がWANなのでport1を選択。<br>
→ 次に接続してくるユーザーにローカルネットワーク上のIPアドレスを割り当てる。DHCPを使うこともできるが、今回は例として 10〜250 の範囲でIPを割り当てる設定にする。<br>
DNSサーバーのIPも設定し（ここではGoogleを使用）、Split Tunnelを有効にする。Split Tunnelとは、指定したネットワーク宛のトラフィックだけを暗号化されたVPN経由で通すという仕組みで、それ以外のトラフィックはインターネットに直接出ていく。もっとシンプルに言うと、YouTubeやGoogle検索はVPNを通らない。業務サーバー向けのトラフィックだけがVPNを経由する形だ。これにより一般的なインターネット利用のスピードが改善され、社内ネットワークへの負荷も下がる。<br>
→ Split Tunnelを有効にしたら、先ほど作ったFirewall Addressを設定するのを忘れずに。ここでは「local_network」という名前にした。

![alt text](images/fortigate-ipsec/remote-new.png)

### 認証

次は認証の設定だ。<br>
プリシェアードキーを設定する（サイト間VPNと同じ要領で）。ただし今回はIKE1のAggressiveを選択する。IKE2を使った方が本来はいいのだが、試したときに設定が保存できなかった。VMの制限が原因かもしれない（はっきりとはわからない）。もしIKE2を試す場合は、EAPも有効にする必要がある（IKE2を選択すると表示されるはずだ）。

IKE1のAggressiveモードは、最初のネゴシエーションメッセージにユーザーの識別情報を含めて送る方式だ。これによりリモートユーザーのIPアドレスが不明でもFortigateがユーザーを特定できる。リモートユーザーは動的IPを使っていることが多い（特に外出先では）ため、固定IPが双方に必要なIKE1のメインモードでは対応できないケースがある。Aggressiveモードはその制約を回避できる反面、この識別情報は暗号化されていないため、攻撃者がネットワーク上でハンドシェイクを盗聴できてしまうリスクがある。IKE1は推奨されないが、今回のチュートリアルではこれで進める（他に動く方法がなかったので）。

Accepted peer IDはAny peer IDを選択。XAuth typeはAuto Serverを選択。User groupはSpecifyを選んで、先ほど作ったグループ（ここでは「remote-group」）を追加する。Inherit from policyを選ぶとリモートアクセスのファイアウォールポリシー側でユーザーグループを指定しなければならないので、ここで直接指定した方が楽だ。

## ファイアウォールポリシーの作成

次に、リモートユーザーが 10.1.1.0/24 ネットワークにアクセスできるようにファイアウォールポリシーを作成する。<br>
→ 新しいポリシーを作って名前をつける。<br>
→ Incoming interfaceは先ほど作ったVPNトンネル名を選択。<br>
→ Outgoing interfaceはLAN側のポートを選択。<br>
→ Sourceは「all」に設定する。ユーザーグループはVPN設定側ですでに指定しているのでここでは不要。<br>
→ Destinationは先ほど作ったローカルアドレスを設定。テスト用にこちらも「ALL」にしておく。<br>
→ NATが有効になっていれば無効にする。<br>
→ デバッグが必要になったときのために、Logging OptionsをAll sessionsに変更しておく。<br>
→ OKをクリック。

## FortiClient VPNでログイン

これでようやくすべての設定が完了だ。最初にダウンロードしたFortiClient VPNアプリを起動しよう。

![alt text](images/fortigate-ipsec/forticlient.png)

上記の画面が表示されたら「Configure VPN」をクリック。<br>
次の画面でIPsec VPNのタブを選択し、以下の情報を入力する。<br>
・Connection name：VPNにつけた名前。<br>
・Remote Gateway：FortigateのWAN側IPアドレス（パブリックIP）。Network > Interfacesから確認できる。会社でDDNSを使っている場合はそのDDNSのアドレスを入力してもいい。今回のラボではport1のIPアドレスになる。<br>
「+」をクリックしてAdvanced Settingsを開き、VPN Settings、Phase 1、Phase 2のオプションを入力する。<br>
・Authentication Method：Pre-shared keyを選択し、トンネルに設定したキーを入力。<br>
・IKEはVersion 1、ModeはAggressiveを選択。<br>
・Phase 1とPhase 2の設定はトンネル構成時に設定した内容と合わせること。

![alt text](images/fortigate-ipsec/forticlient2.png)
![alt text](images/fortigate-ipsec/forticlient3.png)

「Save」をクリックするとログイン画面が表示される。先ほど作ったリモートグループのユーザーでサインインして「Connect」をクリック。

![alt text](images/fortigate-ipsec/forticlient4.png)

接続が成功すると下の画像のような画面になる。設定した範囲内のIPアドレスが割り当てられ、バイトの送受信が始まっているのが確認できるはずだ。おめでとう、リモートVPNの完成だ！<br>
最後の確認として、接続後に接続先ネットワーク上のIPアドレス（例：10.1.1.254）にpingを打ってみよう。pingが通れば、リモート接続がしっかり機能している証拠だ。<br>
接続状況はGUIからも確認できる。サイト間VPNのときと同じ要領で、VPN > VPN Tunnelsへ行き、StatusカテゴリのトンネルをダブルクリックすればOKだ。またはダッシュボードに「IPsec」ウィジェットを追加すれば、リアルタイムの接続状況を確認することもできる。
